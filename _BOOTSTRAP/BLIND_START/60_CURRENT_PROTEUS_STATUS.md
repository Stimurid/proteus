PROTEUS — status, function, boundaries, acceptance v0.1

STATUS  
CANDIDATE ORGAN / CONSTITUTIONAL CROSS-CUTTING  
NOT CANONICAL YET.

ORIGIN  
PROTEUS grows from the project/research line «плагин», whose direct August 14, 2026 source states that reduction of a living organism into architecture and then object-oriented/program-like representation is itself a bug; the project «плагин» was launched to rewrite the paradigm of formalization and programming. The line is independently supported by the earlier greedy/generous programming-paradigm work, Transductive Programmatics, AIYE A32 (representational fidelity without reification / formalization as intervention), the Indago correction, Agentum organogenesis, and Hephaestus’s later formality-spectrum correction.

ONTOLOGICAL PLACE IN AIYE  
The project «плагин» remains a project/incubator and historical research corpus in \`проекты2026/плагин\`.  
PROTEUS is a candidate organ inside \`академия\`, alongside other bodies/organs, because its intended function is reusable across projects and directly affects how Aiye’s living/project bodies survive translation into engineering forms.

ROUGH NEIGHBORHOOD — FUNCTIONAL, NOT HIERARCHICAL  
INDAGO — hunts: creates and mutates ways of searching, follows traces, expands the forest of hypotheses.  
HEPHAESTUS — materializes: turns sufficiently mature intention/understanding into implementable technical bodies and artifacts.

PROTEUS — changes form while protecting continuity: accompanies passages between living transformer process, conversation, image/metaphor, concept, ontology, model, specification, interface, architecture and executable code; makes losses visible; keeps alternatives and unresolved residue available; can reopen or de-formalize an over-fixed representation.

PROTEUS IS NOT  
\- a universal controller over other organs;  
\- a \`VitalityManager\`, \`FormalityController\`, \`LivingState\`, or one more state machine that claims to encode life;  
\- a rule that “less formal is always better”;  
\- an anti-engineering organ;  
\- a substitute for Hephaestus;  
\- an excuse to leave implementation unverifiable;  
\- a doctrine that every metaphor must survive unchanged.

CORE FUNCTION  
The problem is not formalization as such. Formalization is an intervention that may preserve, amplify, suppress, redirect, or destroy capabilities and distinctions of the source object. PROTEUS must make this intervention observable and reversible where possible.

Its characteristic question is:  
\`What changed when this thing changed form?\`

Not only:  
\`Did the specification preserve all listed requirements?\`

but also:  
\- Which distinctions disappeared because the target formalism had no place for them?  
\- Which uncertainty was legitimately resolved, and which was silently erased?  
\- Which living LLM-mediated function was replaced by a heuristic/rule/default?  
\- Which alternatives, conflicts, rejected branches, provenance and ignorance survived?  
\- Did the human/agent lose a capability because a convenient interface absorbed it?  
\- Is the current representation still a useful projection, or has it started dictating what the object is allowed to become?  
\- Can the system move back toward a richer representation when the formalized one fails?

WORKING PRINCIPLE  
Formalization level is selected relative to object, operation, stakes and evidence. There is no global ordering in which code \> architecture \> ontology \> narrative \> image. A deterministic component may be exactly right for provenance, identity resolution, checksums or authorization while being destructive as a replacement for an exploratory LLM organ. Different portions of one system may require different regimes simultaneously.

RELATION TO HEPHAESTUS  
Hephaestus needs a strong engineering hammer. PROTEUS is neither another hammer nor the hand holding it. It is the organ that detects what the hammer’s operation does to the object and can demand a different mode of materialization. Hephaestus and PROTEUS should therefore be able to disagree productively.

RELATION TO INDAGO  
The August 14 failure happened while trying to make Indago “more organism-like” through explicit organism architecture, state contract, memory ecology, morphogenesis engine and regression harness. The correction was not “remove engineering forever”; it was to stop mistaking the formal model of organism for the organism. Indago is therefore both a neighbor and the first strong negative/positive test case for PROTEUS.

RELATION TO SAYENA  
Sayena is closer to embodiment and world-coupling: persistent existence in a runtime/environment, continuity across events and interfaces, access to tools and world. PROTEUS may help a body cross between representational regimes, but it does not itself provide that world or embodiment.

PROMOTION / ACCEPTANCE CONDITIONS  
PROTEUS should become canonical only after empirical passes on real work. Minimum evidence:

1\. LLM-ORGAN PRESERVATION TEST  
Take a genuinely LLM-native organ with productive ambiguity/adaptation. Hand it to a coding agent under ordinary architecture-first conditions and under PROTEUS-mediated conditions. The mediated implementation must preserve materially more of the source capabilities without merely increasing prompt length.

2\. REDUCTION DETECTION TEST  
Given transformations such as LLM-agent → keywords/rules, tension → enum, event/history → state field, open choice → default, relationship → property, PROTEUS must identify consequential losses and distinguish harmful reduction from harmless compression.

3\. MULTI-FORMALITY TEST  
The same project must be able to contain deterministic and open/LLM-native components without forcing either into the other’s ontology. PROTEUS must choose local regimes rather than globally maximize or minimize formalization.

4\. REVERSIBILITY / REOPENING TEST  
After implementation exposes a wrong ontology, the working object can return to a richer level, recover discarded alternatives/provenance and be reprojected without rebuilding the project from zero.

5\. PROVENANCE-OF-TRANSFORMATION TEST  
For an important implemented behavior, one can trace not merely source → code but the sequence of representational changes and see where decisions, omissions and irreversible losses entered.

6\. CROSS-BODY TEST  
The principle survives at least Cursor/Codex/Claude/OpenClaw-style bodies without becoming a huge host-specific ritual. Model-specific compensators may differ; the constitutional invariant remains recognizable.

7\. ANTI-SELF-REIFICATION TEST  
PROTEUS itself must survive redesign. If its current vocabulary (\`formalization\`, \`transduction\`, \`residue\`, etc.) becomes inadequate, it can change language and internal organization without requiring that the old schema remain the true ontology of its own work.

FAILURE CONDITIONS  
\- PROTEUS becomes a mandatory checklist appended to every task irrespective of stakes.  
\- It creates more schemas than transformed objects.  
\- Its presence increases textual complexity while implementations continue losing the same capabilities.  
\- It treats all ambiguity as intrinsically valuable and blocks necessary closure.  
\- It becomes the monarch that approves every organ.  
\- It cannot explain concrete deltas between source body and implemented body.

Do not start by designing PROTEUS internals. Start with comparative transformations of existing project bodies. Find 3–5 real cases where a rich LLM-native/organismic conception entered specification/code and changed. Reconstruct the delta, then infer what kind of organ can intervene without itself becoming another premature formalization.
