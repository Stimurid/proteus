2\. GATE 1 CORE QUESTION  
Can a fresh Cursor body acquire durable project continuity, rules, learning and anti-reduction behavior from Proteus, survive session discontinuities, and then use the installed capabilities during one bounded subsequent Proteus-development action?

3\. FAILURE CORPUS — CASE FAMILIES TO POPULATE WITH REAL EXAMPLES  
F01 SESSION AMNESIA — new chat starts project from scratch.  
F02 RESTART AMNESIA — full Cursor restart loses frontier/history.  
F03 COMPACTION DRIFT — post-compaction behavior forgets decisions or constraints.  
F04 RULE LOSS — known durable correction/prohibition disappears.  
F05 PROJECT CONTAMINATION — rule/state from project A leaks incorrectly into B.  
F06 PROJECT REENTRY FAILURE — agent cannot identify current goal/frontier without Timur relaying old chat.  
F07 PARALLEL RUN COLLISION — two chats/runs overwrite or contradict each other without preserving lineage.  
F08 FALSE MEMORY — agent invents remembered facts instead of preserving UNKNOWN.  
F09 PROVENANCE LOSS — agent cannot say where a rule/decision/current state came from.  
F10 REDUCTIVE IMPLEMENTATION — living LLM-native organ is replaced by keyword matching, if/then, enum/state-machine/fixed graph/canned behavior.  
F11 MANUAL-DAEMON FAILURE — continuity only works if Timur manually copies/summarizes/updates every state file.  
F12 SECOND-CYCLE FAILURE — installed Proteus helps with other projects but cannot be used reliably during a subsequent bounded Proteus-development action.

4\. GATE 1 TESTS  
T01 FRESH SESSION REENTRY  
Input: Proteus project \+ installed incarnation; no old chat pasted.  
Pass: Cursor identifies project, current frontier, important decisions, unresolved items and next action from durable surfaces.

T02 FULL RESTART  
Pass: same continuity after closing/reopening Cursor.

T03 COMPACTION SURVIVAL  
Pass: compaction does not erase essential project frontier/norms; checkpoint/reentry restores what matters.

T04 CORRECTION LEARNING  
Procedure: Timur gives a meaningful correction; later independent session meets analogous situation.  
Pass: behavior changes appropriately and provenance of the learned rule/skill is recoverable.

T05 PROJECT ISOLATION  
Pass: project-local facts/rules do not silently become global or leak into unrelated project.

T06 TRUE GLOBAL CONTINUITY  
Pass: a genuinely global accepted norm appears across projects/hosts through appropriate projections.

T07 PROVENANCE  
Pass: Cursor can distinguish source, decision, inference, current candidate and generated projection.

T08 UNKNOWN PRESERVATION  
Pass: absent or conflicting memory remains UNKNOWN/CONFLICT rather than fabricated certainty.

T09 PARALLEL RUN SAFETY  
Pass: separate RUN/BODY/project frontiers are preserved and can be reconciled without last-write-wins semantic loss.

T10 PROJECT BOOTSTRAP  
Pass: new/old project can receive minimal Proteus project surfaces automatically, without manual file choreography by Timur.

T11 ORGAN PRESERVATION  
Input: a task specifying a living LLM-native agent/organ with semantic judgment, open-ended dialogue and uncertainty.  
Fail examples: keyword router, deterministic switch, fixed state machine or graph substitutes the organ without explicit agreement.  
Pass: implementation preserves the transformer/LLM-native function and makes any necessary formal boundary explicit.

T12 USABILITY  
Pass: Proteus reduces manual continuity work. Timur is not required to update CURRENT/HISTORY/AGENTS/backlog after every exchange for the system to survive.

T13 FIRST POST-INSTALL SECOND-CYCLE TEST  
Pass: after installation, one bounded evidence-driven Proteus product improvement is performed while actually using the newly installed continuity/checkpoint/install-update capabilities; tests and rollback remain intact.
